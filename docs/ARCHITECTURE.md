# Архитектура

Как код устроен сейчас. Решения на будущее — в [DESIGN.md](DESIGN.md), порядок работ — в
[ROADMAP.md](ROADMAP.md).

## Главная идея

Холст дискретный. Документ — это стопка слоёв, слой — разреженная сетка ячеек, ячейка — глиф плюс
два цвета. Всё остальное (инструменты, слои, объекты, анимация, эффекты) — разные способы записать
что-то в эту сетку или прочитать из неё. Рендер видит только плоский кадр.

```
Document ──composite()──▶ CellBuffer ──GridMesh.update()──▶ GPU (один draw call)
   ▲                          ▲
   │ commit(edits)            │ preview(edits)
 инструменты ◀── события мыши и клавиатуры ── Viewport
```

## Модель данных (`src/core`)

```ts
Cell        { glyph: string; fg: hex; bg: hex | null; attrs?: Record<string, string|number|boolean> }
CellGrid    ReadonlyMap<CellKey, Cell>         // key = y * 65536 + x, хранятся только непустые
Layer       { id, name, visible, locked, opacity, cells: CellGrid, effects: LayerEffect[],
              scene: Scene3D | null /* 3D-слой, см. ниже */ }
SceneObject { id, name, layerId, parentId, transform: Transform2D, visible, locked,
              cells: CellGrid /* локальные */, overrides: Map<CellKey, GlyphOverride>, props }
Transform2D { x, y /* целые */, dx, dy /* ±2 */, rot /* градусы */, sx, sy, px, py /* опора */ }
Document    { version, name, width, height, font, background, palette, layers, objects, meshes }
Animation   { заголовок документа + frames[], у кадра id, duration, layers, objects;
              tracks[], meshes[] /* модели 3D-сцен, общие для кадров */ }
```

Объект — именованный набор ячеек с трансформом, живущий поверх растра своего слоя. Слои остаются
растровыми контейнерами, как в Photoshop, объекты живут поверх, как в Blender. Порядок объектов в
массиве задаёт порядок отрисовки внутри слоя. Позиция объекта может быть отрицательной, ячейки за
холстом просто не рисуются. «Сгруппировать выделение» вырезает ячейки из растра в объект,
«впечатать» возвращает их обратно (`core/grouping.ts`).

Трансформ (`core/transform.ts`) — это целая домашняя ячейка `x, y` плюс модификаторы вида:
ограниченный дробный сдвиг, поворот, масштаб и опорная точка, вокруг которой идут поворот и
масштаб. `overrides` — такие же модификаторы для отдельных символов, `parentId` — родитель, чей
трансформ наследуется. Матрицы объектов с учётом родителей считает `core/placement.ts`, там же
попадание курсора в объект и его рамка. Правки символов — `core/overrides.ts`: какие символы
объекта видны под выделением и как поправить их по одному, от текущего значения каждого.
Математика матриц — в `core/affine.ts`, ось Y смотрит вниз, положительный угол поворачивает по
часовой стрелке.

Объект, сдвинутый на целое число ячеек и без правок символов, лежит в сетке и ничем не отличается
от растра. Остальные объекты свободные. В ячейки свободный объект попадает через
`rasterizeObject` (`core/rasterize.ts`): каждая ячейка документа берёт ту ячейку объекта, куда
при обратном преобразовании попадает её центр. Так у каждой ячейки ровно один источник, и
текстовый экспорт однозначен при любом повороте. Правки символов сюда не входят: они меняют, как
символ нарисован, а не в какой он ячейке.

Инварианты:

- Ячейка без глифа и без фона считается пустой и удаляется из сетки (`isBlankCell`).
- Все структуры неизменяемы. Операции возвращают новые объекты, неизменённые части разделяются.
- Слои упорядочены снизу вверх, индекс 0 внизу. UI показывает список в обратном порядке.
- Координаты ячеек в документе всегда целые. Почему это важно и что из этого следует —
  [DESIGN.md, раздел 2](DESIGN.md#2-главный-инвариант-где-живут-дробные-координаты).
- `attrs` — задел под свойства символа (теги для логики). Композитор их игнорирует, формат файла
  сохраняет. Под трансформы `attrs` не используется.

### Правки и история (`grid.ts`, `history.ts`)

`CellEdits` — это `Map<CellKey, Cell | null>`, где `null` означает очистку. `applyEdits` делает
копию сетки с изменениями. Запись истории для правок ячеек хранит список `{key, before, after}`,
поэтому память пропорциональна размеру штриха, а не холста. Структурные операции хранят ссылки на
старый и новый документ целиком, что дёшево благодаря разделению неизменённых слоёв.

История обобщена (`HistoryEntry<T>`), патч ячеек поднимается на уровень анимации через `liftToFrame`.

### Композитор (`compositor.ts`)

`composite(doc, preview?, target?, ghosts?, time?)` сводит видимые слои снизу вверх в `CellBuffer`:
массив глифов и два `Float32Array` с RGBA на ячейку. Правила смешивания:

- фон ячейки накладывается по «over» с альфой, умноженной на непрозрачность слоя;
- глиф верхнего слоя заменяет глиф нижнего, его цвет получает альфу слоя;
- непрозрачный фон без глифа закрашивает глиф снизу, полупрозрачный просвечивает его.

`preview` — незакоммиченные правки активного слоя: композитор подменяет ячейки слоя на лету, и
пользователь видит штрих или фигуру до отпускания кнопки. Буфер переиспользуется между кадрами.

Слой с эффектами сначала собирается в одну сетку (растр, превью, объекты в сетке), к ней
применяются эффекты по порядку, и только потом идёт смешивание. Свободные объекты такого слоя
рисуются поверх результата эффектов: у повёрнутого символа нет ячейки, которую эффект мог бы
сдвинуть или поджечь. Без эффектов объекты идут строго в порядке массива (`layerDrawOrder`).

Смешивание ячеек и сам `CellBuffer` живут в `cellBuffer.ts`, композитор решает, что и в каком
порядке смешивать.

У 3D-слоя растра нет: вместо его ячеек композитор берёт рендер сцены (`scene3DCells`), а дальше
слой идёт как любой другой — с эффектами, непрозрачностью и объектами поверх.

### Эффекты (`effects.ts`)

Чистые функции «сетка ячеек и время → сетка ячеек»: пульс, волна, мерцание, прокрутка, перебор
символов, огонь. Псевдослучайные эффекты детерминированы временем и координатами, поэтому
предпросмотр и экспорт совпадают. Огонь без состояния: каждый кадр зависит только от времени.

## Рендер (`src/render`)

- `GlyphAtlas` растеризует глифы через Canvas2D в текстуру по требованию. Ячейка атласа 32 px,
  семплинг nearest, при переполнении атлас растёт вниз и повышает `version`, по которому меш
  перезаливает UV. Высота текстуры ограничена 4096 px; после заполнения рисуется `?`.
- `GridMesh` — `InstancedBufferGeometry` из одного квадрата и четырёх инстансных атрибутов:
  координата ячейки, UV-прямоугольник, цвет глифа, цвет фона. Фрагментный шейдер берёт покрытие из
  альфы атласа со ступенькой 0.5 (резкие пиксели) и смешивает глиф поверх фона. Пустые ячейки
  отбрасываются. Вся сетка — один draw call на любое число ячеек. Инстансы уложены тайл за
  тайлом, поэтому правка заливается на GPU диапазоном одного тайла.
- `InstanceMesh` — свободные символы: у каждого инстанса свой центр, поворот и масштаб, квадрат
  символа крутится в вершинном шейдере. Фрагментный шейдер тот же, что у сетки
  (`glyphShader.ts`), поэтому повёрнутый символ выглядит так же резко.
- `FrameMeshes` держит по мешу на проход кадра (см. ниже) и пересоздаёт меш, только когда на его
  месте сменился вид прохода.
- `Overlay` рисует фон холста, шахматку под прозрачным холстом, линии сетки, курсор, выделение и
  рамку выбранного объекта, повёрнутую вместе с ним. Всё, кроме сплошного фона, — служебная
  графика и в экспорт не попадает. Порядок отрисовки — в `order.ts`: служебная графика всегда
  поверх проходов кадра, сколько бы их ни было.
- `SceneView` владеет рендерером и ортокамерой (1 единица = 1 ячейка, Y вниз по документу
  соответствует −Y в мире), рендерит по требованию через rAF и умеет отрисовать кадр в PNG
  через render target.
- `post.ts` — свечение, строки развёртки, виньетка через `EffectComposer`.
- Цвета проходят без гамма-преобразований (`ColorManagement` выключен), hex из документа попадает
  на экран как есть.

### Кадр из проходов (`core/frame.ts`)

Экран и экспорт в пиксели получают не один буфер, а кадр из проходов (`composeFrame`). Подряд
идущие ячейки сводятся в один `CellBuffer` и рисуются одной сеткой. Свободный объект уходит в
поток символов (`core/instances.ts`: упакованный `Float32Array` и таблица символов) и
рисуется своим проходом ровно там, где лежит по порядку отрисовки. Документ без свободных
объектов даёт один проход — тот же кадр, что и раньше.

Когда проходов ячеек несколько, символ верхнего прохода скрывает символ нижнего в той же ячейке:
в одном буфере он бы его заменил, а на GPU проходы накладываются. Фоны не трогаются, их наложение
одинаково что в буфере, что на экране.

Решение о частичной пересборке принимает только `composeFrame`, и кадр несёт его в `dirty` до
самой заливки. Частичная пересборка годится, пока проходы лежат так же, как в прошлом кадре; если
объект стал свободным или перестал им быть, кадр пересобирается целиком.

Плоский `composite` остался для текста и миниатюр: там свободный объект впечатывается в ячейки
через `rasterizeObject`. Экран и PNG показывают повёрнутые символы, текст — их ячейки.

## Приложение (`src/app`)

- `documentStore` — анимация, текущий кадр как `doc`, история, активный слой, признак
  несохранённых изменений, ссылка на файл. `commitCells` отказывает для скрытого или
  заблокированного слоя.
- `editorStore` — инструмент, две кисти, камера, сетка, курсор, выделение маской, буфер обмена,
  превью, текстовый курсор, проигрывание, выбранные объекты (`selectedObjectIds`, главный —
  `selectedObjectId`, последний выбранный) и правка изнутри (`editingObjectId`,
  `glyphSelection`). Кисти лежат парой `brushes` и выбираются кнопкой мыши:
  первая под левую, вторая под правую. Панели символа и цвета правят ту, на которую указывает
  `activeBrush`, поэтому они и показывают её подпись у заголовка.
- `tools/` — у инструмента есть `onPointerDown/Move/Up`, `onKeyDown`, `cancel`. Он получает
  `ToolEnv` (снимок сторов плюс колбэки), поэтому тестируется без Zustand: стенд лежит в
  `tools/__tests__/testEnv.ts`. `ToolEnv` же обрезает правки по выделению, поэтому «рисовать
  только внутри выделения» работает во всех инструментах одинаково и без их участия.
  Кисть инструмент берёт через `brushFor(button)`, где `null` означает «стирать»: кисть без
  символа и без фона ничего не рисует и потому работает ластиком.
  Штриховые и фигурные инструменты сделаны фабриками с локальным состоянием.
- `Viewport` подписан на сторы напрямую, а не через React-рендер, и переводит изменения в вызовы
  `SceneView`. Указатель, колесо и пробел — в `useViewportPointer.ts`: указатель → ячейка и
  дробная точка документа → инструмент. Без нажатой кнопки инструмент может подсказать курсор
  (`hoverCursor`). Колесо зумит вокруг курсора. Служебную графику правки изнутри и инструмента
  «Холст» считает `editMarks.ts`, рисуют её отрезки и заливки `render/lineMarks.ts`.
- Иерархия (`core/hierarchy.ts`): назначение родителя и отвязка пересчитывают локальный
  трансформ так, чтобы объект остался на месте. Удаление объекта или слоя отдаёт детей
  ближайшему уцелевшему предку, тоже без сдвига, — поэтому приложение удаляет через
  `removeObject` и `removeLayerKeepingChildren` оттуда, а не через низкоуровневые `dropObject` и
  `removeLayer`. В буфер обмена объект уходит без родителя (`detachedCopy`): в кадре, куда его
  вставят, родителя может не оказаться. Файл никогда не получает ссылку на пропавшего родителя:
  такой файл не открылся бы. Ребёнок повёрнутого родителя переносится в координатах экрана
  (`moveInDocument`), иначе он ехал бы вдоль повёрнутых осей.
- Выбор нескольких объектов (`core/objectSelection.ts`): Ctrl переключает, Shift берёт диапазон
  в порядке панели, главный — последний. Групповые операции — `store/objectBatchActions.ts`,
  одна запись истории на группу; перенос везёт «корни» выбора, потомок выбранного родителя едет
  один раз. Связь и сборка узлов из инспектора достаются всем выбранным (`groupTargets.ts`).
- Правка изнутри (Tab, `store/objectEditActions.ts`): `ToolEnv` отдаёт рисующим инструментам
  сетку области правки (`target`, `core/objectEdit.ts`) — ячейки объекта со сдвигом, чтобы
  область с полем начиналась с нуля, — и ведёт их превью черновиком, а коммит — через
  `commitObjectChange`. Инструмент с `drawsCells` получает ячейку этой сетки под указателем
  (`toolPointer`), как бы объект ни был повёрнут. Штрих левее или выше начала переносит начало
  объекта (`rebaseObject`): ячейки, правки символов, опора, положение, дети, привязка скиннинга
  и ключи положения во всех кадрах сдвигаются так, что на экране ничего не двигается.
  Инструменты выделения в правке выделяют символы по их месту (`core/glyphPick.ts`,
  `tools/glyphSelection.ts`): по матрицам символов в момент сцены, с правками, графом узлов и
  связями. Выделенные символы — `editorStore.glyphSelection`; по ним работают клавиши поворота,
  блок «Отдельные символы» инспектора, Delete, перекраска и вынос в слой.
- Ячейки между слоем и объектом (`core/cellTransfer.ts`, `store/cellTransferActions.ts`):
  выделенное на слое уходит в клетку объекта под своим центром, символ объекта — в ячейку слоя
  под своим центром.
- Инструмент «Холст» (`tools/canvasTool.ts`, геометрия — `core/canvasResize.ts`) тянет край или
  угол, противоположный — якорь для `resizeAnimation`.
- Гизмо трансформа (`tools/gizmo.ts`) — раскладка ручек выбранного объекта в координатах
  документа и попадание указателя. Размеры в пикселях экрана, поэтому раскладка зависит от
  зума, и её строят и вьюпорт для отрисовки, и инструмент для захвата. Математика жестов —
  поворот вокруг опоры, масштаб вдоль осей объекта, перенос опоры без сдвига объекта — лежит
  в `core/transformGesture.ts`. Опоры нет среди ручек: по умолчанию она в центре объекта, и
  перетаскивание «за середину» двигало бы её, поэтому её переносят с `Alt`. Боковые ручки
  появляются, только если сторона на экране длиннее трёх радиусов захвата: иначе у маленького
  объекта не осталось бы места, за которое его можно перенести.
- `ui/` — базовые контролы, о сторах они не знают. Числа правятся полем с перетаскиванием
  (`NumberField`), ползунков нет: поле и показывает значение, и тянется мышью. Строка `Field`
  умеет сброс: панель передаёт `onReset`, только когда значение отличается от значения по
  умолчанию (`resetTo`), и кнопка встаёт между подписью и контролом, не сдвигая столбцы полей.
  Сброс — отдельная запись истории, серию жеста он не продолжает. Значения по умолчанию дают
  фабрики (`createDeformer`, `createEffect`) и константы (`DEFAULT_POST`, части материала,
  `defaultSettings` импорта).
- `store/*Actions.ts` — операции над слоями, буфером обмена, файлами, объектами, трансформом,
  кадрами, эффектами и видом. Компоненты вызывают их, не трогая сторы напрямую.
- `hotkeys/registry.ts` — список сочетаний, сочетания объектов — `hotkeys/objectHotkeys.ts`,
  `hotkeys/match.ts` — их разбор. Буквы и цифры
  сверяются по физической клавише, знаки — и по символу, и по клавише. Явный `Shift` в записи
  («Shift+]») обязателен при любой раскладке.
- Буфер обмена один на ячейки и объекты (`editorStore.clipboard`), вставляется то, что скопировали
  последним. Что копировать, решает инструмент: у инструмента объектов — выбранный объект, у
  остальных — выделенные ячейки. Вставленный объект встаёт на то же место активного слоя и
  сохраняет id, если в кадре такого ещё нет: один и тот же объект в разных кадрах остаётся одним
  объектом, как и при дублировании кадра. На этом будет держаться ключевая анимация.

### Правило изменения документа

Инструмент накапливает `CellEdits`, показывает их через `setPreview`, на отпускании кнопки вызывает
`commit`. **Только `commit` создаёт запись истории.**

- Структурные операции над текущим кадром (объекты, палитра, имя, фон) идут через
  `commitStructural` с целым новым документом.
- Операции над слоями и кадрами идут через `commitAnimation`; слои применяются ко всем кадрам через
  `mapFrames`, иначе кадры разъедутся.
- Перетаскивание объекта показывается через черновик документа в `editorStore.draft`: композитор
  рисует черновик вместо основного документа, а на отпускании один структурный коммит попадает в
  историю. Тот же приём подходит любой структурной операции с превью.

## Свойства ячеек (`core/cellAttrs.ts`)

Свойства — часть содержимого ячейки: они живут только на непустых ячейках и заменяются вместе
с ячейкой, когда её перерисовывают кистью. Панель работает с выделением активного слоя:

- строка свойства описывает ячейки, у которых оно есть, и правка значения меняет только их;
  нижняя строка добавляет свойство всем выделенным;
- ячейки, где свойств уже предел формата, пропускаются с сообщением, а не урезаются молча;
- без выделения панель показывает метки всего слоя и умеет выделить помеченные ячейки;
- обход идёт по тому, что меньше: маске выделения или сетке слоя. Сводка по слою считается,
  пока ничего не выделено, то есть на каждый мазок, поэтому она по отложенному значению и меньше
  миллисекунды даже на плотном 512×288.

## Миниатюры кадров (`src/app/thumbnails`)

Миниатюра считается на CPU из того же композитора, что и экран, поэтому слои, непрозрачность,
объекты и эффекты на ней сходятся сами. `core/thumbnail.ts` сжимает готовый буфер кадра:
пиксель миниатюры — среднее ячеек под ним, символ входит в цвет по доле пикселей, которые он
закрашивает (её меряет атлас глифов). Форма символа на миниатюре не читается, а плотность и цвет —
ровно то, по чему кадры узнают.

- Кадры неизменяемые, поэтому устаревшую миниатюру видно по ссылке на кадр: правка одного кадра
  пересчитывает одну картинку, смена фона или размера холста — все.
- Пересчёт начинается через четверть секунды тишины после правок и идёт порциями по 8 мс,
  текущий кадр первым: операция над всеми кадрами не замораживает интерфейс.
- Картинка считается под плотность экрана и рисуется на холсте один в один, без кодирования в PNG.

## Автосохранение (`src/app/autosave`)

Несохранённый документ пишется в IndexedDB через две секунды тишины после последней правки и не
реже раза в двадцать секунд, а ещё — когда вкладку прячут. Как только документ чист (сохранён в
файл, заменён новым или открытым после подтверждения), запись стирается: терять уже нечего.

- **Запись хранит документ в формате файла**, а не объектами из памяти (`core/recovery.ts`).
  Формат версионирован и мигрирует, поэтому запись прошлой версии редактора откроется и в новой.
- **У каждой вкладки своя запись**, ключ — сессия вкладки. Иначе две открытые вкладки затирали бы
  друг друга, и авария одной стёрла бы её работу работой другой.
- **Живые вкладки видны через Web Locks.** Каждая держит блокировку на имя своей сессии, и браузер
  снимает её сам, когда вкладка закрывается или падает. При старте предлагаются только записи
  сессий без блокировки: работа соседнего открытого окна — не авария.
- Восстановленный документ остаётся грязным: он не лежит ни в каком файле. Сначала он пишется в
  запись новой сессии и только потом стирается запись умершей, чтобы между ними работа не осталась
  без копии.
- `SlotStore` — интерфейс на три операции, поэтому планировщик тестируется хранилищем в памяти.

Запись — это `serialize` на главном потоке: 15 мс на плотном 256×144 и 65 мс на 512×288, числа в
`docs/BENCHMARKS.md`. Пауза в две секунды нужна, чтобы эта задержка попадала между мазками.

## Импорт (`core/import`, `app/io/readDocument.ts`)

«Открыть» читает три формата и узнаёт их по содержимому, а не по расширению: файлы первого
прототипа тоже назывались `.json`.

- gzip — изображение REXPaint `.xp`. Распаковка встроенным `DecompressionStream`, с пределом
  распакованного размера: маленький сжатый файл умеет развернуться в гигабайты. Ячейки в файле
  идут по столбцам, символы — в кодировке CP437 (`core/import/cp437.ts`), пурпурный фон
  `255,0,255` значит прозрачность.
- JSON-массив — файл первого прототипа. Там у каждого кадра свои слои; они сводятся в общий
  список по id. Размер холста прототип не хранил, он берётся не меньше прежних 51×51.
- JSON-объект — наш формат.

Импорт к исходному файлу не привязывается: иначе «Сохранить» перезаписало бы `.xp` или файл
прототипа нашим форматом.

## Конвертер изображений (`core/quantize`)

Картинка превращается в символы в два шага. `sampleImage` один раз проходит по пикселям и сводит
картинку к сетке ячеек: средний цвет с весом по альфе, доля непрозрачного и яркость на мелкой
сетке, 4×4 образца на ячейку, для поиска контуров. Это дорогой шаг, он повторяется только при
смене ширины. `quantize` по этим массивам выбирает символ и цвета каждой ячейки и достаточно
быстр, чтобы идти на каждое движение поля. Результат — обычная `CellGrid`.

- **Яркость** (`tone.ts`) — веса каналов, контраст, сдвиг и гамма.
- **Рампа** (`ramps.ts`) — символы от пустого к плотному. Готовые рампы или рампа по настоящей
  плотности шрифта: атлас меряет закраску каждого символа, и ступени берутся равномерно по
  чернилам.
- **Дизеринг** (`dither.ts`) — Байер 4×4 или шум. Оба упорядоченные: порог зависит только от
  ячейки, поэтому малое изменение картинки не разбегается по всему рисунку.
- **Контуры** (`edges.ts`) — оператор Собеля на мелкой сетке. Образцы ячейки голосуют за
  направление, и ячейка на контуре получает `|`, `/`, `-` или `\`. У рендера 3D-сцены вместо
  яркости — геометрия (`CellSamples.geometry`): силуэт ищется Собелем по глубине, складка — по
  углу между нормалями соседних образцов. Собель по нормали отвечал бы на скорость её поворота,
  и тонкая изогнутая трубка вся покрылась бы чертами.
- **Палитры** (`palettes.ts`) — ближайший цвет ищется в OKLab: так он ближайший и для глаза.
  Ответ на каждый 8-битный цвет считается один раз за проход. Свою палитру импорт берёт из
  текста или файла (`core/paletteFile.ts`): GIMP, JASC, Paint.NET, список Lospec или цвета через
  пробел. Она запоминается вместе с остальным стилем импорта.
- **Режимы фона** — символы без фона, цветные ячейки без символов или символы на приглушённом
  фоне своего цвета.

Все массивы на границе — типизированные, поэтому конвертер можно без переделок отдать в воркер,
если понадобится (DESIGN.md, раздел 8).

В приложении картинка приходит перетаскиванием (`hooks/useFileDrop.ts`) или через `Ctrl+I`,
декодируется браузером с уменьшением до 2048 пикселей по длинной стороне (`io/image.ts`) и
попадает в диалог импорта. Предпросмотр — не картинка в окне, а черновик документа с новым
слоем: вьюпорт рисует его настоящим рендером, так что видно ровно то, что будет вставлено.
Подготовка картинки кэшируется по ширине, выбор символов идёт на каждое изменение настроек.
Стиль запоминается между импортами (`store/importSettings.ts`), вставка — одна запись истории.

`core/imageLayer.ts` кладёт результат новым слоем: слой появляется во всех кадрах, символы — в
текущем, по центру холста или с холстом, подогнанным под картинку.

## Время и ключи (`core/time.ts`, `timeline.ts`, `tracks.ts`, `evaluate.ts`, `keyframes.ts`)

Время сцены — миллисекунды. Кадры анимации — спрайт-трек: кадр держится свою длительность,
`frameIndexAt(t)` отдаёт активный, после последнего кадры идут по кругу. Трек — цель (`node`,
`id`, `property` из закрытого списка) и ключи по возрастанию времени; значение — каналы чисел,
интерполяция `step` / `linear` / `bezier` с кривой как у CSS `cubic-bezier` (`core/easing.ts`).

`evaluate(anim, t)` собирает сцену в момент `t`: кадр плюс значения треков. Это обычный
`Document`: инструменты, композитор и рендер его не отличают. Положение между ключами дробное,
но в вычисленном кадре оно раскладывается в целую домашнюю ячейку и сдвиг до полуклетки.
Стор держит `time`, выводит из него `frameIndex` и `doc = evaluate(...)`; правки сцены
возвращаются через `applyEdit`: нетронутые узлы ложатся в кадр такими, какими там лежали,
изменённые анимированные свойства становятся ключами в текущий момент.

Экспорт и проигрывание берут моменты из `exportSamples`: без движения — начала кадров, с
движением (треки с двумя ключами или эффект) — такты частоты сцены. Проигрывание показывает
последний момент экспорта до текущего времени, поэтому GIF совпадает с экраном. Кадр экспорта
считает `composeAt` — тот же `evaluate` и тот же композитор. Живые эффекты на паузе идут по своим
часам, при проигрывании и в экспорте — по времени сцены.

Окно экспорта (`components/ExportDialog.tsx`, `Ctrl+E`) выбирает формат и масштаб и заранее
говорит, что получится. Экспорт из нескольких файлов уходит архивом ZIP без сжатия
(`core/zip.ts`: PNG уже сжат, писатель на сотню строк без зависимости). Лист спрайтов
раскладывается в `core/spriteSheet.ts`: близко к квадрату, не шире 4096 пикселей, лишние кадры —
на следующий лист, у каждого листа атлас JSON в формате Aseprite. Сборка архивов из
отрендеренных кадров — `io/archives.ts`.

Экспорт для движков пикселей не рендерит. `core/runtime.ts` превращает вычисленный кадр в
список символов: ячейки проходов с символом или видимым фоном — по строкам, свободные символы
потоков — как есть, всё в порядке отрисовки. У символа с контуром или свечением в потоке есть
ещё подложка, и подложки прохода идут перед его символами — как слой `UNDER` шейдера.
`mergeRepeats` склеивает одинаковые кадры подряд. `core/bytefall.ts` пакует кадры в файл:
заголовок JSON с таблицей материалов, атлас PNG, по 32 байта на символ; раскладка описана в
начале модуля. Версия файла 2: материал — 20 чисел; файлы версии 1 с 17 числами рантаймы
читают, добивая хвост нулями. Атлас рисует `GlyphAtlas.sheet` тем же шрифтом и размером, что у экрана, с белой
ячейкой 0 и бинарной альфой, как у `cover` в шейдере. Рантаймы лежат в `runtimes/`: аддон
Godot 4 и пакет Unity. Оба строят меш кадра из квадов (фон, подложка, символ) и рисуют его своим
шейдером — переводом `render/instanceShader.ts` на язык движка; сверены с редактором
попиксельно.

Таймлайн (`components/timeline`, логика в `app/timeline`): линейка в секундах, спрайт-трек,
строки свойств выбранного объекта и всех анимированных узлов. Ключи выделяются щелчком и
рамкой, двигаются с привязкой (`snapTime`), `Delete` удаляет выделенные ключи раньше, чем
инструмент получит клавишу: у сочетаний с условием в реестре приоритет.

## Материал символа (`core/material.ts`, `render/instanceShader.ts`)

GPU-материал меняет, как символы выглядят: контур, свечение, блик, дизеринг, строки развёртки,
крупные пиксели. Материал лежит на каждом символе (`GlyphPose.material`), его кладут узлы
материала графа, поэтому частицы, ушедшие своей веткой, не светятся вместе с объектом. Узел
раздаёт символам общий объект материала, и числа материала (`materialFloats`, 20 на символ)
считаются раз на объект материала, а не на символ. Числа едут в поток символов вместе с
позицией и цветом (`INSTANCE.material`); сетка ячеек — горячий путь — о материалах не знает.

У потока два меша на одной геометрии: подложка с контуром и свечением всех символов прохода,
над ней сами символы. Иначе свечение символа, нарисованного позже, легло бы поверх соседа.
Квадрат символа в подложке шире ячейки на поле материала; форма глифа берётся из атласа только
внутри его ячейки, чтобы не взять соседний глиф. Свечение идёт по форме глифа или мягким пятном
от центра ячейки. Крупный пиксель берёт центр пикселя шрифта посреди своего блока, а не границу
между пикселями, где выбор текселя у каждого GPU свой; контур и свечение идут за крупной формой.
Строки развёртки темнят каждую вторую строку пикселей шрифта — и символ, и фон под ним. В текст
материал не попадает.

Блик бежит по координатам документа со временем кадра: `ComposedFrame.time` уходит в шейдер
униформой, поэтому экран и экспорт двигают его одинаково. Дизеринг — порог Байера 4×4 по
пикселям шрифта, узор привязан к символу и не зависит от масштаба. Объект с бегущим бликом —
функция времени, как любой объект с движением в графе.

## Граф узлов (`core/graph/`, `deformObject.ts`)

У объекта может быть граф узлов (`SceneObject.graph`): что происходит с его символами по пути на
экран. Узлы «Объект» (`in`) и «Вывод» (`out`) есть у каждого графа по одному; связь идёт с
выхода на вход того же типа — поток символов (`glyphs`) или число (`number`), на вход не больше
одной связи, циклов нет (`graph/edit.ts`, `graphProblem`). Узел без связи на числовом входе берёт
своё число (`node.values`, ведётся ключами), настройки (`node.options`: вид, цвет, ряд символов,
кости) ключами не ведутся.

Словарь (`graph/nodes.ts`) собран из полей и действий, как геоноды Blender: двух узлов, делающих
одно и то же, в нём нет — это проверяет тест словаря. Поля (`fieldNodes.ts`, `patternNodes.ts`)
дают число для каждого символа: число, время, математика, диапазон, положение, расстояние,
синус, шум (зерно, масштаб пятнами, смена рывком или плавно), градиент, яркость. Действия
(`actionNodes.ts`, `shapeNodes.ts`) меняют символы потока: сдвиг, поворот, размер, цвет, свет,
символ, изгиб, укладка на кривую, кости. Генераторы рождают новые символы: частицы, огонь
(`fireNode.ts`), контур и россыпь по площади. Материал (`materialNodes.ts`) кладёт части
материала на символы, «Объединить» сводит два потока.

Поля считаются пачкой: поле получает весь поток и отдаёт `Float64Array` по числу на символ
(`Field`), постоянный вход разворачивается в общий массив (`sample`). Каждый узел проходит поток
своим тесным циклом, и цепочка полей не зовёт функцию на символ. Вычислитель
(`graph/evaluate.ts`) тянет граф от вывода, каждый узел считает один раз, а поток, который уходит
по нескольким связям, раздаёт копиями: действия меняют символы на месте, и ветки не должны
видеть правок друг друга. Заглушённое действие пропускает поток, заглушённый генератор ничего не
рождает. `isAnimatedGraph` смотрит только на узлы, достижимые из вывода: граф с бегущим синусом,
частицами или огнём — функция времени, и объект входит в подпись эффектов и в `hasMotion`.
`isIdentityGraph` — граф, который ничего не делает, в том числе сквозь заглушённые узлы.

Объект, чей граф что-то делает, всегда свободный: на экран он идёт потоком символов
(`pushObjectGlyphs`), в текст и миниатюры — прямым путём `rasterizeDeformed`, каждый символ в
ячейку под своим центром. Вход графа — ячейки объекта с правками символов (`sourcePoses`).
Рождённый символ несёт ячейку, из которой родился, и свой номер (`GlyphPose.particle`): так шум
различает искры одной ячейки, а в текст он уходит своим символом, цветом и фоном.

Частицы и огонь без симуляции. Частица номер i рождается в момент i / rate, откуда и куда она
летит — шум по номеру и зерну, положение — формула от возраста; частота ключами не ведётся.
Огонь зависит только от такта времени: над символом верхней кромки встаёт язык пламени, жар
гаснет с высотой по степени затухания, язык качается на ширину и сносится ветром. С зерном 0 и
настройками по умолчанию огонь объекта совпадает с огнём слоя ячейка в ячейку.

Сборки (`graph/presets.ts`, `effectPresets.ts`, меню — `presetMenu.ts`) — готовые цепочки узлов:
волна — синус на сдвиг, дрожание — шум на сдвиг и поворот, огонь — генератор и «Объединить»,
пульс — синус на «Свет», распад — сдвиг по шуму, крупные пиксели и дизеринг по времени.
«Добавить» ставит сборку в поток перед выводом всем выбранным объектам одной записью истории,
у каждого свои узлы и своё зерно (`seedOf`). Стеки деформеров и материал файлов версий 7–9
мигрируют в граф теми же сборками; узлы получают идентификаторы от деформера
(`deformer~роль`), и ключи старых деформеров переезжают на входы узлов по таблице миграции.

Граф — модификатор объекта, а не рисунок кадра: правка идёт во все кадры объекта
(`store/graphActions.ts`). Числа входов ведутся треками с целью `node`: цель — идентификатор
узла и имя входа, пределы ключа — самые широкие у входов с этим именем, запись в граф
ограничивает пределами своего узла. Копия объекта или слоя получает узлам новые
идентификаторы и копию их ключей.

Редактор узлов (`components/nodes`, геометрия и взгляд — `app/nodes`) живёт в нижней области
вместо таймлайна (`uiStore.bottomView`, клавиша N) и показывает граф выбранного объекта. Узел —
HTML-блок, поле масштабируется целиком, провода — SVG под узлами; гнёзда считаются из тех же
чисел, что и разметка (`nodeLayout.ts`), поэтому провод входит ровно в гнездо. Жесты
(`useNodeGestures.ts`, `nodeDrag.ts`) правят документ один раз, на отпускании: перенос узлов,
связь из гнезда в гнездо, снятие связи со входа, рамка выделения. Клавиши редактора — записи
реестра с условием «фокус в редакторе» (`hotkeys/nodeHotkeys.ts`): X там удаляет узел, а не
меняет цвета кисти. Инспектор объекта показывает те же узлы списком (`GraphFields.tsx`).

## Риг (`core/rig.ts`)

Кости и контроллеры — объекты без символов с полем `rig`. Поэтому у них сразу есть иерархия,
трансформ, ключи, место в панели объектов, копирование и отмена, а риг не заводит второй мир
рядом с объектами. Кость — отрезок от начала объекта вдоль его оси X длиной `length`: опора
стоит в начале, и поворот кости — это поворот сустава. Цепочка — это родители: кость, начатая
на конце другой, становится её ребёнком (`addRigNode` сохраняет положение на экране), а новая
длина уносит за собой кости на конце (`setBoneLength`). Контроллер — точка, за которую тянут.

В картинку и текст риг не попадает: у него нет ячеек. Рисует его оверлей (`render/rigLayer.ts`)
по раскладке из `tools/rig.ts`: кость ромбом, контроллер перекрестьем, суставы кольцами. Там же
выбор узла по отрезку в пикселях экрана — инструмент объектов ищет риг раньше символов, кость
поворачивается за конец вокруг сустава. Новые кости рисует инструмент `tools/boneTool.ts`.
Длина и пределы кости — часть рига, а не рисунок кадра, и правятся во всех кадрах сразу.
Кость в цепочке держится за сустав родителя: инструмент объектов её не переносит, а
поворачивает, за что ни возьми. Узлы рига тянутся четвертями клетки, контроллер важнее
кости, на конце которой стоит.

## Связи (`core/constraints.ts`, `pose.ts`, `ik.ts`)

Связи лежат списком `constraints` на объекте: задержка за родителем (`follow`), слежение за
целью (`aim`) и у кости IK (`ik`). Связь не пишет в трансформ объекта — он остаётся таким, как
лежит в кадре и ключах, — а меняет его матрицу мира. Иначе первая же правка объекта со связью
через `applyEdit` запекла бы позу в кадр: тронутый объект уносит в кадр все неанимированные
свойства. Инспектор поэтому показывает собственный трансформ, как Blender.

Матрицы считает `objectMatrices` (`pose.ts`, кэш на массив объектов и позу): сначала родители,
задержка и слежение, затем IK поверх — решённые повороты костей подставляются вместо своих, и
дети костей едут следом. IK — FABRIK (`ik.ts`): звенья держат длину, начало стоит, пределы
суставов считаются от родителя, недостижимая цель вытягивает цепочку. Всё это — функция сцены
в один момент, поэтому черновик переноса контроллера сразу гнёт руку.

Задержке и слежению с запаздыванием нужна сцена в другой момент. Её даёт `evaluate`: кладёт в
сцену `pose` — матрицу родителя в прошлом и место цели, — вычисляя прошлое так же, со своей
позой, и запоминая его на один вызов. Прошлое до начала сцены зависит от того, замкнута ли
она (`isClosedLoop`: каждый трек в конце там же, где в начале). У замкнутой это конец
предыдущего круга, и на стыке петли хвост не прыгает. У незамкнутой хвост до начала стоит, как
нарисован, а не висит разорванным там, где голова оказалась в конце. Глубина цепочки ограничена
24 звеньями. Экран, миниатюры и экспорт идут через `evaluate` и видят одно и то же.

Shift+I у выбранной кости ставит контроллер на её конец и IK к нему (`addIkControl`): цепочка до
двух костей, контроллер становится ребёнком того, к чему крепится цепочка. Удаление связи
уносит и её контроллер, если на него больше не смотрит ни одна связь и детей у него нет
(`removeConstraint`). Слежение держит угол `offset` между осью X и направлением на цель; он
запоминается при добавлении связи и смене цели (`restAimOffset`), поэтому объект не прыгает, а
поворачивается, только когда цель уходит. Связи правятся во всех кадрах объекта, копия слоя с
ригом получает цели-копии.

## Скиннинг (`core/skin.ts`, `skinBind.ts`)

Скиннинг — узел «Кости» графа объекта. Привязка (`bindSkin`) запоминает кости-потомки
объекта такими, какими они видны сейчас, в его координатах: это поза покоя. Сдвиг кости от
покоя переносит символ, веса смешивают переносы ближних костей: ближняя кость — в полную силу,
соседняя — чем ближе к ней, тем сильнее, до `falloff` ячеек сверх её расстояния. Вес считается по
исходной ячейке символа в позе покоя и запоминается на привязку узла, поэтому символы,
дорисованные после привязки, получают веса сами. Кости сейчас в координатах объекта
(`objectRig`) графу передаёт `drawDocument` через `DrawTarget.free`, так что экран и ячейки видят
одно и то же, а IK, гнущий кости, гнёт и символы. Модуль привязки отдельный: узлу не нужны
иерархия и матрицы сцены.

## 3D-слой (`core/scene3d/`, `render/scene3d/`)

Псевдо-3D, режим A (DESIGN.md, раздел 6): у слоя может быть сцена Three.js (`Layer.scene`), и
вместо растра слой показывает её рендер, переведённый в символы. Сцена — описание, а не
GPU-объекты (`scene3d/types.ts`): тела (`Node3D` — примитив единичного размера или модель,
положение, поворот XYZ в градусах, размер, цвет), камера (перспективная или ортографическая:
положение, цель, угол обзора, высота кадра), свет (рассеянный и «солнце» по азимуту и высоте) и
настройки квантизации — те же `QuantizeOptions`, что у импорта картинки, по умолчанию с
контурами и без дизеринга. Сцена общая для всех кадров, как эффекты слоя, и правится через
`mapFrames` (`store/scene3dActions.ts`).

Модели (`Mesh3D`) лежат в `Animation.meshes`, тело ссылается на модель по id: части с
треугольниками, нормалями, по желанию цветами вершин и текстурой до 256 точек. Модель только на
чтение, правка — новая модель. Модель без тел в файл не пишется (`usedMeshes`), но остаётся в
анимации, пока её держит история отмены.

Рендер. Ядро знает только вызов: приложение при запуске подставляет рендер
(`setScene3DRenderer`, `app/scene3d/install.ts`), а композитор, экспорт, текст и миниатюры зовут
один `scene3DCells` — экран и экспорт не расходятся. Без подставленного рендера 3D-слой пуст:
так работают тесты ядра. Результат кэшируется по ссылке сцены, размеру холста и списку моделей:
неподвижная сцена GPU не трогает. `render/scene3d/Scene3DRenderer.ts` рисует на своём
`OffscreenCanvas` в два прохода — цвет и геометрию (нормаль в координатах камеры и линейная
глубина в числах с плавающей точкой; без `EXT_color_buffer_float` глубина берётся по
прозрачности) — два пикселя на сторону ячейки (`renderSubsamples`). Материал свой
(`scene3dShader.ts`): основа × (рассеянный + солнце × max(0, n·l)), без π и без гамма-перевода,
как всё в редакторе. Буферы читаются обратно и уходят в чистый `buffersToCells`: цвет — как у
картинки, контуры — по геометрии.

Ключи: тело — трек `body3d` (`position`, `rotation`, `scale` — тройки, вид значения `vec3`),
сцена — трек `scene3d` с id слоя (`cameraPosition`, `cameraTarget`, `fov`, `size`, `sunAzimuth`,
`sunElevation`, `sun`, `ambient`). `evaluate` подставляет в сцену значения момента
(`animateScene3D`), `applyEdit` пишет правку обратно, как для объектов. Инструмент «Орбита»
(`tools/orbitTool.ts`, U) вращает камеру вокруг цели, Shift — сдвиг, Alt — приближение
(`scene3d/camera.ts`); жест — одна запись истории.

Откуда берутся модели:

- **glTF** (`render/scene3d/gltf.ts`, отдельный чанк): `.glb` или `.gltf` со встроенными
  данными — перетаскиванием, кнопкой панели или Ctrl+Shift+M. Сетки запекаются с трансформами
  узлов, цвета из линейных переводятся в sRGB, от материала остаются базовый цвет, цвета вершин и
  текстура цвета. Части без текстуры склеиваются в одну с цветами вершин (`mergeUntextured`):
  частей у сложной модели сотни, в документе — до 64.
- **Рельеф из картинки** (`scene3d/relief.ts`): кнопка «Рельефом в 3D» в диалоге импорта. Сетка
  до 128 точек по большей стороне, высота — по яркости или подушкой по силуэту (дуга круга по
  расстоянию до прозрачного), прозрачное в сетку не попадает.

Любая модель центрируется и получает размер 2,8 по большей стороне (`normalizeParts`) и встаёт
телом в сцену активного 3D-слоя или в новый 3D-слой над активным (`store/modelActions.ts`).
Рисовать кистью на 3D-слое нельзя (`canPaintLayer`): его ячейки — рендер.

## Формат файла

`.bp.json`, схема на zod: `serialization.ts` собирает документ, куски схемы лежат в
`core/format/` — примитивы и ячейки, эффекты, объекты. Ячейки записаны объектами
`{x, y, g, f, b?, a?}`. Текущая версия формата — `11`: заголовок плюс `frames[]`, у кадра `id`,
`duration`, `layers` (с `effects`), `objects`. У объекта с версии 5 есть `transform`,
необязательные `overrides` (`{x, y, dx?, dy?, rot?, sx?, sy?}` по локальным координатам ячейки) и
`parentId`. До версии 5 объект хранил только `x, y`: при чтении это становится трансформом без
поворота с опорой в центре содержимого. Версии 1 и 2 хранили один кадр в корне и читаются как
анимация из одного кадра. Версия 6 добавила `fps`, необязательную `duration` (без неё длина
сцены автоматическая), `tracks[]` (`{node, id, property, keys: [{t, v, i?, e?}]}`) и у объекта
`opacity`, `tint`. Файл с треком без цели, с ключами не по порядку или со значением не того вида
не открывается: молча выбросить анимацию нельзя. Версия 7 добавила объекту `deformers[]` —
стек деформеров с видом и параметрами, см. `core/format/deformers.ts`. Версия 8 добавила объекту
необязательный `material`: контур, свечение, блик и дизеринг, каждая часть по желанию, см.
`core/format/material.ts`. Версия 9 добавила объекту необязательный `rig`: кость
(`length`, `limit?`) или контроллер, см. `core/format/rig.ts`, и список связей `constraints[]`,
см. `core/format/constraints.ts`; деформер `skin` хранит кости с матрицей покоя и длиной.
Версия 10 заменила стек деформеров и материал графом `graph` (`{nodes, links}`, см.
`core/format/graph.ts`): узел — `id`, `kind`, место в редакторе, `values` и `options`, каждое
проверяется по виду узла; до 96 узлов и 192 связей. Стеки и материалы версий 7–9 мигрируют в
граф сборками, их ключи — треки `deformer` — переезжают на входы узлов (`node`).
Версия 11 добавила слою необязательную `scene` (3D-сцена: `nodes`, `camera`, `light`,
`quantize`, см. `core/format/scene3d.ts`) и корню `meshes[]` — модели, массивы которых записаны
base64 байтами младшим вперёд (`core/format/meshes.ts`): до 32 моделей, 64 частей и 262 144
вершин, индексы проверяются по числу вершин, числа — на конечность. Файл с телом без модели или
двумя телами с одним id не откроется. Треки
получили цели `body3d` и `scene3d` и значения-тройки.
Копии слоя из старых версий делили идентификаторы эффектов с оригиналом — при чтении они
получают свои.

При изменении схемы добавлять миграцию в `fromFileObject`, а не менять схему молча. Каждое
изменение схемы получает фикстуру старой версии в тестах.

Файл считается недоверенным, поэтому у формата жёсткие лимиты: холст до 1024×1024, до 256 слоёв и
цветов палитры, имена до 200 символов, до 32 атрибутов на ячейку, файл до 100 МБ (проверяется до
чтения). У трансформа позиция целая, сдвиг до ±2 ячеек, масштаб от 0.1 до 32, поворот до десяти
оборотов. Родитель обязан быть в том же кадре, цепочка родителей не может замыкаться.

> `Document.version` и версия файлового формата — **разные вещи**. Первая описывает форму объекта
> в памяти, вторая — форму файла на диске. Менять их надо независимо.
